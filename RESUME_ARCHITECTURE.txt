1. VUE D'ENSEMBLE
================================================================================

Système de téléopération temps réel permettant de piloter un véhicule
autonome miniature depuis un PC distant. Le système remplace le VNC
(1-2 FPS) par un streaming JPEG-over-TCP (~30 FPS, <50ms de latence).

Deux modes de fonctionnement :
  • Mode Manuel (TÉLÉOP)  — Pilotage RC temps réel depuis le PC (actif)
  • Mode Autonome (PID)   — Suivi de murs par LIDAR (code préservé, désactivé)

3. PROTOCOLE DE COMMANDES (TCP:8884)
================================================================================

Format : messages texte UTF-8 terminés par \n

  COMMANDE CONTINUE (utilisée par le client RC) :
  ──────────────────────────────────────────────
  TELEOP:DRIVE,<vitesse>,<angle>\n

  Exemples :
    TELEOP:DRIVE,0.1800,0.3000   → avancer à 18%, braquer 30% droite
    TELEOP:DRIVE,0.0000,0.0000   → arrêt
    TELEOP:DRIVE,-0.1200,0.5000  → reculer à 12%, braquer 50% droite

  Valeurs :
    vitesse ∈ [-1.0, 1.0]   positif = avant, négatif = arrière
    angle   ∈ [-1.0, 1.0]   négatif = gauche, positif = droite

  COMMANDES DISCRÈTES (rétrocompatibilité) :
  ──────────────────────────────────────────
    TELEOP:FWD     → vitesse = 0.15
    TELEOP:BWD     → vitesse = -0.10
    TELEOP:LEFT    → angle -= 0.1
    TELEOP:RIGHT   → angle += 0.1
    TELEOP:STOP    → vitesse = 0, angle = 0
    on / off       → active/désactive la boucle (legacy)

4. CONTRÔLES RC (teleop_client.py)
================================================================================

  Architecture multi-thread :
  ─────────────────────────
    Thread 1 (VideoReceiver) : réception JPEG continue, indépendant
    Thread principal          : clavier + envoi commandes + affichage HUD

    Avantage : le flux vidéo ne gèle JAMAIS même quand des touches
    sont maintenues. Les touches sont COMBINABLES (Z+Q = avancer+gauche).

  Touches simultanées via bibliothèque 'keyboard' :
  ─────────────────────────────────────────────────
    Z         → accélérer (rampe progressive + kick-start initial de 6%)
    S         → reculer  (rampe progressive + kick-start initial de 6%)
    Q         → tourner à gauche (pas de 0.08 par tick)
    D         → tourner à droite (pas de 0.08 par tick)
    Z+Q       → avancer ET tourner gauche en même temps
    Z+D       → avancer ET tourner droite en même temps
    S+Q / S+D → reculer ET tourner
    ESPACE    → arrêt d'urgence (vitesse = 0, angle = 0)
    T         → test servo (cycle angles -1, -0.5, 0, +0.5, +1)
    R         → recentrer la direction
    ESC       → quitter

  Chronogramme d'une commande :
  ────────────────────────────
    t=0.00s  Touche Z enfoncée
    t=0.00s  speed = 0.06 (kick-start, franchit l'inertie)
    t=0.03s  speed = 0.072 (+0.012 par tick à 30 Hz)
    t=0.07s  speed = 0.084
    ...      rampe progressive jusqu'à max 0.18
    t=1.00s  Touche Z relâchée
    t=1.03s  speed = 0.18 × 0.90 = 0.162 (décélération auto)
    t=1.07s  speed = 0.162 × 0.90 = 0.146
    ...      freinage progressif
    t=2.50s  speed < 0.015 → speed = 0 (dead zone)

  Paramètres ajustables (en tête de teleop_client.py) :
  ─────────────────────────────────────────────────────
    MAX_FWD_SPEED  = 0.18     # vitesse max avant
    MAX_BWD_SPEED  = -0.12    # vitesse max arrière
    ACCEL_STEP     = 0.012    # accélération par tick
    KICK_START     = 0.06     # boost initial au démarrage
    DECEL_FACTOR   = 0.90     # coefficient décélération
    ANGLE_STEP     = 0.08     # incrément direction par tick
    ANGLE_RETURN   = 0.04     # rappel au centre par tick

5. CHAÎNE DE COMMANDE SERVO (DIRECTION)
================================================================================

  teleop_client.py
       │
       │  TELEOP:DRIVE,0.18,0.50
       ▼
  ServeurTcp::getDatas()      → émet signal newDatas("TELEOP:DRIVE,0.18,0.50")
       │
       ▼
  Controleur::onoff()         → détecte préfixe "TELEOP:" → handleManualCommand()
       │
       ▼
  Controleur::handleManualCommand()  → parse speed=0.18, angle=0.50
       │                              → emit deplacer(0.18, 0.50)
       ▼
  MaterielReel::deplacer()
       │
       ├──► setI2CMotor(0.18)        → I2C /dev/i2c-1, adresse 0x58 (MD04)
       │                                 Dir: 2, Vitesse: 45
       │
       └──► direction.setPosition(0.50)
                │
                ▼
            ServoMoteur::updatePos()
                │  duty = (0.50 × 300 + 1500) × 1000 = 1650000 ns
                │
                ▼
            PWM::setDuty(1650000)
                │
                ▼
            Écrit dans /sys/class/pwm/pwmchip0/pwm0/duty_cycle
                │
                ▼
            GPIO 18 (pin physique 12) ─── Signal PWM 50 Hz ──► Servo direction

  Valeurs caractéristiques du servo :
  ──────────────────────────────────
    angle = -1.0  →  duty = (−1.0 × 470 + 1500) × 1000 = 1030000 ns = 1030 µs
    angle =  0.0  →  duty = ( 0.0 × 300 + 1500) × 1000 = 1500000 ns = 1500 µs
    angle = +1.0  →  duty = (+1.0 × 300 + 1500) × 1000 = 1800000 ns = 1800 µs

6. CONFIGURATION MATÉRIELLE (RASPBERRY PI 4)
================================================================================

  /boot/firmware/config.txt :
  ─────────────────────────
    dtparam=i2c_arm=on
    dtoverlay=pwm-2chan,pin=18,func=2,pin2=19,func2=2

  Broches utilisées :
  ──────────────────
    GPIO 18 (pin 12)   → PWM0 (servo direction) via dtoverlay
    SDA1 / SCL1        → I2C bus 1 (moteur MD04, adresse 0x58)
    /dev/ttyUSB0       → LIDAR RPLidar (USB)
    /dev/ttyAMA1       → TFmini (UART)
    CSI                → Picamera2

  Résolution du problème PWM :
  ───────────────────────────
    Problème : le code original utilisait pwmchip2/channel2 (inexistant)
    
    Étape 1 : dtoverlay=pwm-2chan,pin=12 → crée pwmchip0 mais servo
              ne répond pas (pas le bon GPIO)
    Étape 2 : dtoverlay=pwm-2chan,pin=18 → servo répond sur pwmchip0/pwm0
              Le servo est physiquement câblé sur GPIO 18 (pin 12)
    
    Solution finale : pwmchip0, channel 0, overlay pin=18

7. PROBLÈMES RÉSOLUS
================================================================================

  [1] VNC à 1-2 FPS → JPEG-over-TCP à 30 FPS
  [2] Segfault LIDAR → null-guard drv + timer stop
  [3] PWM chip/canal → pwmchip0/pwm0 (était pwmchip2/pwm2)
  [4] GPIO servo     → GPIO 18 pin=18,func=2 (pas GPIO 12)
  [5] I2C init MD04  → stabilisation au bout de quelques secondes
  [6] Stream gelé    → VideoReceiver en thread séparé
  [7] 1 touche max   → bibliothèque keyboard (touches simultanées)
  [8] Démarrage mou  → kick-start de 6% au premier appui

9. POUR RÉACTIVER L'AUTONOMIE
================================================================================

  Dans controleur.h, changer :
      bool modeManuel{true};   →   bool modeManuel{false};

  Ou ajouter une commande TCP "AUTO:ON" dans handleManualCommand() :
      modeManuel = false;
      isRunning = true;

  Le code PID (computeError, pid.update, speedCtrl) est 100% intact.
